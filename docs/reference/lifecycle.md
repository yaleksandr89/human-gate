# Жизненный цикл капчи

Human Gate хранит сведения о созданной капче, следит за сроком её действия и числом неверных попыток. После правильного ответа эта капча больше не принимается. Общие ограничения настраиваются через [`Policy`](api.md#policy).

## Срок действия и ограничения

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `ttlSeconds` | `180` | Сколько секунд действительна капча |
| `maxWrongAttempts` | `3` | Число неверных попыток |
| `maxActive` | `12` | Число одновременно активных капч |
| `maxActivePerPurpose` | `4` | Число активных капч одного назначения |
| `maxTombstones` | `32` | Число записей о завершённых капч |
| `terminalRetentionSeconds` | `180` | Время хранения записей о завершённых капч, если их не удалят раньше из-за лимита |

Все значения должны быть положительными, а `maxActivePerPurpose` не может превышать `maxActive`. Для увеличения времени действия до пяти минут используется `new Policy(ttlSeconds: 300)`.

Ограничения числа активных капч относятся к хранению данных. Они не заменяют ограничение частоты HTTP-запросов.

## Создание капчи

[`ChallengeService::issue()`](api.md#issue) создаёт новую капчу выбранного вида. При успехе приложение получает идентификатор, время окончания и данные для отображения.

Если лимит активных капч уже достигнут, возвращается `LifecycleCode::CapacityExceeded`, а новая капча не создаётся. По умолчанию метод создаёт [текстовую капчу](../challenges/text-image.md), для остальных видов указывается `ChallengeKind`.

## Проверка ответа

[`ChallengeService::verify()`](api.md#verify) получает идентификатор капчи, её назначение и ответ пользователя. Назначение выбирает приложение на сервере. Вид капчи определяется по сохранённым данным, поэтому передавать его из браузера не нужно.

Ответ проверяется по правилам соответствующего вида. Для [`CategorySelection`](../challenges/category-selection.md) порядок токенов не важен; для [`IconSequence`](../challenges/icon-sequence.md) он учитывается. Неверный формат ответа также считается неверной попыткой.

## Неверный ответ

Каждый неверный ответ увеличивает счётчик попыток. Пока лимит не достигнут, сервис возвращает `VerificationCode::Incorrect`: с той же капчей можно попробовать ещё раз.

Ответ, которым достигается предел, возвращает `VerificationCode::AttemptsExhausted`. При стандартных настройках **третья неверная попытка** завершает капчу. Дальнейшая проверка по тому же идентификатору не принимается, а время действия не увеличивается.

Чтобы продолжить, приложение создаёт новую капчу через [`issue()`](api.md#issue): обновить через `replace()` капчу с исчерпанными попытками уже нельзя.

## Правильный ответ

При правильном ответе сервис возвращает `VerificationCode::Accepted`. После этого ту же капчу нельзя пройти повторно. Пока запись об успешной проверке сохранена, повтор возвращает `AlreadyConsumed`.

Приложение выполняет обработку формы после `Accepted`. Отправка письма, запись в базу и другие действия выполняются приложением, отдельно от проверки капчи.

## Обновление капчи

[`ChallengeService::replace()`](api.md#replace) создаёт новую капчу вместо прежней. При успехе приложение получает другой идентификатор и новые данные. Старый ответ и выбранные варианты больше не подходят.

Обновление доступно для действующей капчи или для истёкшей, пока запись о ней сохраняется. При замене действующей капчи общее количество активных капч не увеличивается. Для замены истёкшей капчи может потребоваться свободное место в хранилище.

Если капча уже пройдена, ранее обновлена или исчерпала попытки, заменить её этим методом нельзя. По умолчанию новая капча будет текстовой; для другого вида его нужно указать явно.

## Истечение срока и удаление записей

Капча действительна, пока текущее время меньше `expiresAt`. Начиная с указанного момента правильный ответ по ней не принимается.

Сведения об истёкшей капче могут некоторое время оставаться в хранилище. Пока они есть, `verify()` возвращает `Expired`, а `replace()` может создать новую капчу. После удаления сведений старый идентификатор возвращает `NotFound`.

Записи о завершённых капч сохраняются ограниченное время. Если число таких записей превышает `maxTombstones`, старые записи могут удаляться раньше. Поэтому для давно истёкшей капчи не гарантируется отдельный результат `Expired`: после удаления записи будет `NotFound`.

## Назначение капчи

`Purpose` связывает капчу с формой или действием, для которого она была создана. Значение задаётся приложением на сервере. Если назначение не совпадает, проверка возвращает `PurposeMismatch` и не принимает ответ. Подробнее о формате `Purpose` — в [справочнике API](api.md#основные-типы).

## Результаты методов

| Метод | При успехе | Другие результаты |
| --- | --- | --- |
| [`issue()`](api.md#issue) | `Issued` и новая капча | `CapacityExceeded` |
| [`replace()`](api.md#replace) | `Refreshed` и новая капча | `CapacityExceeded`, `NotFound`, `PurposeMismatch`, `AttemptsExhausted`, `AlreadyConsumed`, `Replaced` |
| [`verify()`](api.md#verify) | `Accepted` | `Incorrect`, `AttemptsExhausted`, `Expired`, `NotFound`, `PurposeMismatch`, `AlreadyConsumed`, `Replaced` |

Сбои хранилища или создания изображений приводят к исключениям, а не к результату `Incorrect`. Приложение обрабатывает их отдельно, как описано в [справочнике API](api.md#исключения).
