# Жизненный цикл проверки

Каждое задание CAPTCHA имеет идентификатор, назначение, срок действия и ограничение числа неверных ответов. Human Gate хранит эти данные на сервере, проверяет ответы и не позволяет использовать принятое задание повторно.

## Настройка ограничений

Ограничения задаются объектом [`Policy`](api.md#policy). Значения по умолчанию:

| Параметр | Значение | Для чего нужен |
| --- | --- | --- |
| `ttlSeconds` | `180` | Сколько секунд действует задание |
| `maxWrongAttempts` | `3` | Сколько неверных ответов допустимо |
| `maxActive` | `12` | Сколько действующих заданий может храниться одновременно |
| `maxActivePerPurpose` | `4` | Сколько действующих заданий может относиться к одному назначению |
| `maxTombstones` | `32` | Сколько записей о завершённых заданиях сохраняется |
| `terminalRetentionSeconds` | `180` | Сколько секунд хранятся записи о завершённых заданиях, если их не удалят раньше из-за лимита |

Все значения положительные; `maxActivePerPurpose` не может быть больше `maxActive`. Время действия можно увеличить, например, с помощью `new Policy(ttlSeconds: 300)`.

## Создание задания

[`ChallengeService::issue()`](api.md#issue) создаёт задание выбранного типа и возвращает его идентификатор, время окончания и данные для отображения. По умолчанию создаётся [`TextImage`](../challenges/text-image.md); для других типов указывается соответствующий `ChallengeKind`.

Если лимит действующих заданий уже достигнут, возвращается `LifecycleCode::CapacityExceeded`, а новое задание не создаётся. Ограничения количества заданий относятся к серверному хранилищу, а не к частоте HTTP-запросов.

## Проверка ответа

[`ChallengeService::verify()`](api.md#verify) использует идентификатор и назначение, выбранное приложением на сервере. Тип задания определяется по сохранённым данным, поэтому браузер не выбирает, какую проверку выполнять.

Для действующего задания ответ проверяется по правилам его типа. `CategorySelection` принимает выбранные токены в любом порядке, а `IconSequence` учитывает их порядок. Некорректный формат ответа считается неверной попыткой.

## Неверные ответы

Неверный ответ увеличивает число использованных попыток. Пока лимит не достигнут, метод возвращает `VerificationCode::Incorrect`, а пользователь может попробовать ещё раз с тем же заданием.

Ответ, которым достигается установленный предел, возвращает `AttemptsExhausted`; задание больше не принимается. При настройках по умолчанию это **третий неверный ответ**. Неверные попытки не продлевают срок действия.

После исчерпания попыток приложение создаёт новое задание через `issue()`. Обновить прежнее через `replace()` уже нельзя.

## Правильный ответ

Успешная проверка возвращает `VerificationCode::Accepted`, после чего тот же идентификатор задания нельзя использовать повторно. Пока запись об успешной проверке сохранена, повтор возвращает `AlreadyConsumed`.

Приложение выполняет защищаемое действие только после `Accepted`. Например, отправка письма или запись в базу данных остаются отдельной операцией приложения; библиотека не выполняет их автоматически.

## Обновление задания

[`ChallengeService::replace()`](api.md#replace) создаёт новое задание вместо старого. При успешном обновлении приложение получает новый идентификатор и новые данные для отображения. Старый ответ и выбранные варианты больше не подходят.

Можно обновить действующее задание или истёкшее задание, запись о котором ещё хранится. При обновлении действующего задания общий лимит активных проверок не увеличивается. Для истёкшего задания может понадобиться свободное место в хранилище.

Если задание уже принято, заменено или исчерпало попытки, обновление не выполняется. По умолчанию новое задание имеет тип `TextImage`; для другого типа его нужно явно указать.

## Истечение срока и удаление записей

Задание действительно, пока текущее время меньше `expiresAt`. Начиная с `expiresAt`, правильный ответ больше не принимается.

Информация об истёкшем задании может сохраняться некоторое время. Пока она есть, проверка возвращает `Expired`, а обновление через `replace()` может создать новое задание. После удаления старой записи идентификатор возвращает `NotFound`.

Записи о завершённых заданиях хранятся ограниченное время и ограничены параметром `maxTombstones`. При превышении этого лимита запись может удалиться раньше обычного срока. Поэтому старое истёкшее задание не всегда можно отличить от задания, которого уже нет.

## Назначение проверки

Назначение задаётся объектом [`Purpose`](api.md#основные-типы) и выбирается приложением на сервере. При несовпадении назначения возвращается `PurposeMismatch`; проверка не принимается. Поле из браузера не должно определять назначение защищаемого действия.

## Коды результатов

| Действие | Успех | Что может помешать |
| --- | --- | --- |
| [`issue()`](api.md#issue) | `Issued` и новое задание | `CapacityExceeded` |
| [`replace()`](api.md#replace) | `Refreshed` и новое задание | `CapacityExceeded`, `NotFound`, `PurposeMismatch`, `AttemptsExhausted`, `AlreadyConsumed`, `Replaced` |
| [`verify()`](api.md#verify) | `Accepted` | `Incorrect`, `AttemptsExhausted`, `Expired`, `NotFound`, `PurposeMismatch`, `AlreadyConsumed`, `Replaced` |

Ошибки хранилища и генерации изображений не превращаются в ответ `Incorrect`: это исключения, которые приложение обрабатывает отдельно. Полный список типов и результатов находится в [справочнике API](api.md).
