# IconSequence

## Назначение

Попросите пользователя воспроизвести порядок значков на целевом изображении. `IconSequenceStrategy` создаёт цель и варианты, а `ChallengeService` проверяет последовательность токенов на сервере.

## Что видит пользователь

Пользователь видит целевую последовательность с настроенными помехами и отдельные чёткие изображения вариантов. Он выбирает нужные варианты в том же порядке, в котором значки расположены на цели.

## Быстрый пример

Конфигурация стратегии в composition root после подключения Composer autoload:

```php
use Yaleksandr\HumanGate\IconSequence\IconSequenceBlur;
use Yaleksandr\HumanGate\IconSequence\IconSequenceOptions;
use Yaleksandr\HumanGate\IconSequence\IconSequenceRenderOptions;
use Yaleksandr\HumanGate\IconSequence\IconSequenceStrategy;

$strategy = new IconSequenceStrategy(
    new IconSequenceOptions(sequenceLength: 4, choiceCount: 8),
    new IconSequenceRenderOptions(
        minIconSize: 72,
        maxIconSize: 80,
        blur: IconSequenceBlur::Strong,
        noisePercent: 150,
        maxRotationDegrees: 90,
    ),
);
```

Зарегистрируйте `$strategy` в `ChallengeService`. При `issue()` и `replace()` явно передайте `ChallengeKind::IconSequence`; по умолчанию они выбирают TextImage. Общая сборка и отдельные запросы описаны в [руководстве интеграции](../guides/integration.md).

## Настройки задания

| Поле `IconSequenceOptions` | По умолчанию | Ограничение |
| --- | --- | --- |
| `sequenceLength` | `4` | `3..6` |
| `choiceCount` | `8` | От `sequenceLength + 2` до `12` |

## Настройки отрисовки

| Поле `IconSequenceRenderOptions` | По умолчанию | Ограничение |
| --- | --- | --- |
| `minIconSize` | `72` | `72..96` пикселей |
| `maxIconSize` | `80` | `72..96`, не меньше `minIconSize` |
| `blur` | `IconSequenceBlur::Strong` | `None`, `Light`, `Standard`, `Strong` |
| `noisePercent` | `150` | `0..150` |
| `maxRotationDegrees` | `90` | `0..90` |

Максимальный габарит повёрнутого квадрата должен помещаться в фиксированную высоту цели 128 пикселей. Поэтому допустимость отдельных значений ещё не означает допустимость их сочетания: например, максимальный размер и большой поворот проверяются вместе.

Настройки отрисовки влияют только на цель. `0` отключает соответствующий шум или поворот; `100` задаёт базовую плотность шума. Изображения вариантов остаются чёткими исходными PNG.

## Presentation

`IconSequencePresentation` содержит:

- `target`: целевое `ImagePresentation`;
- `requiredSelections`: необходимое число выборов;
- `choices`: список `IconSequenceChoice` с полями `token` и `image`.

Token — непрозрачная строка из 32 строчных hex-символов. Изображение каждого варианта — PNG `ImagePresentation`. Публичное представление не содержит семантического имени значка, пути файла, признака принадлежности к цели или позиции варианта в правильном ответе.

Приложение строит интерфейс из этих данных и показывает порядок текущего выбора. После успешной замены очистите старую последовательность, токены и ID.

## Формат ответа

Передайте в `verify()` непрозрачные токены через запятую, ровно в порядке выбора пользователя. Порядок значим. Формат допускает 3..6 уникальных токенов по 32 строчных hex-символа; сырой ответ ограничен 197 байтами.

Пакет не нормализует пробелы и не переставляет токены. Приложение не сортирует ответ, не меняет регистр и не удаляет повторения для исправления ввода. Не вычисляйте правильность на клиенте.

Некорректный формат или неверный порядок для активного задания дают `Incorrect` либо `AttemptsExhausted` на границе лимита. Прочие результаты зависят от [жизненного цикла](../reference/lifecycle.md).

## Изображения и размеры

| Изображение | MIME | Размер |
| --- | --- | --- |
| `target` | `image/png` | Ширина `count * 112 + 24`, высота `128`, где `count` — число значков цели |
| Каждый `choice.image` | `image/png` | `96×96` |

`bytes` содержит сырые PNG-байты, не base64; предел одного `ImagePresentation` — 131072 байта. Отрисовка использует `ext-gd`.

Текущий каталог содержит 32 отобранных значка, производных от Tabler Icons `v3.48.0` под MIT. В пакет включены 96×96 PNG. Источник, сведения о преобразовании и контрольные суммы находятся в [метаданных ресурсов](../../resources/icons/tabler/SOURCE.txt), условия — в [MIT](../../resources/icons/tabler/LICENSE.txt).

## Ошибки

Некорректные options, несовместимое сочетание размера и поворота или некорректное прямое конструирование DTO приводят к `InvalidArgumentException`.

Сбои GD, assets и обработки изображения приводят к `RenderingException`; ошибка источника случайности может передаться как `Random\RandomException`. Генерация и отрисовка завершаются до изменения storage. Инфраструктурные ошибки session отдельно выражаются через `NativeSessionStorageException` и не означают неверный ответ пользователя. [API](../reference/api.md) описывает категории ошибок.

## Безопасность

Семантические названия значков намеренно не входят в публичное представление: они раскрывали бы полезные сведения для решения задания. Передавайте полученные изображения и непрозрачные токены без добавления серверных имён, путей ресурсов и разметки правильной последовательности.

Proof связан с ID, purpose, kind и каноническим ответом и остаётся серверным. IconSequence — дополнительный барьер в защите приложения; он не выполняет авторизацию и не гарантирует устойчивость к любому автоматическому распознаванию. Общие правила — в [модели безопасности](../security-model.md).

## Доступность

Для интерактивных вариантов можно использовать нейтральные доступные названия, например «Вариант 1», и объявлять позиции текущего выбора. Такие названия описывают интерфейс, не смысл изображения и не правильную позицию в цели.

Без семантических названий визуальное сопоставление остаётся необходимым. Приложение предоставляет альтернативный путь; нейтральные подписи сами по себе эту задачу не решают. [Рекомендации по доступности](../accessibility.md) описывают клавиатуру, статусы и обновление.
