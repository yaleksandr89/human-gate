# CategorySelection

В этой CAPTCHA пользователь выбирает все карточки, относящиеся к указанной категории. Например, среди названий фруктов и инструментов нужно выбрать только фрукты. Порядок выбора значения не имеет.

## Категории и пример настройки

Категории и подписи карточек задаёт само приложение. Human Gate использует готовый список, выбирает нужное число карточек и проверяет ответ.

```php
<?php

use Yaleksandr\HumanGate\CategorySelection\CategorySelectionCategory;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionOptions;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionStrategy;

$strategy = new CategorySelectionStrategy(
    [
        new CategorySelectionCategory('Фрукты', ['Яблоко', 'Груша', 'Слива', 'Персик']),
        new CategorySelectionCategory('Инструменты', ['Молоток', 'Пила', 'Отвёртка', 'Клещи']),
    ],
    new CategorySelectionOptions(cardCount: 6, targetCount: 2),
);
```

Стратегия регистрируется в `ChallengeService`. При создании задания через [`issue()`](../reference/api.md#issue) нужно указать `ChallengeKind::CategorySelection`, поскольку без явного типа создаётся текстовая CAPTCHA. Полная сборка приведена в [руководстве по интеграции](../guides/integration.md).

Каталог должен содержать от двух до шестнадцати категорий, в каждой от одного до тридцати двух предметов. Для выбранного количества карточек нужны достаточные наборы подходящих и отвлекающих вариантов.

Названия категорий и карточек должны быть уникальными. Текст передаётся в UTF-8, а его длина ограничена 80 байтами. Приложению также важно подбирать категории, которые пользователи не будут путать по смыслу.

## Количество карточек

Параметры `CategorySelectionOptions`:

| Параметр | По умолчанию | Допустимые значения |
| --- | --- | --- |
| `cardCount` | `6` | От `3` до `12` карточек |
| `targetCount` | `2` | От `1` до значения меньше `cardCount` |

`cardCount` задаёт общее число карточек, а `targetCount` — число карточек из нужной категории. Остальные карточки выбираются из других категорий.

Срок действия и количество попыток определяет общая [`Policy`](../reference/api.md#policy), а не `CategorySelectionOptions`.

## Данные для отображения

[`CategorySelectionPresentation`](../reference/api.md#данные-для-интерфейса) содержит поле `category` с названием нужной категории и список `cards`. Каждая `CategorySelectionCard` содержит `label` для показа пользователю и случайный `token`, который используется в ответе.

В браузер не отправляется признак правильности отдельной карточки. Названия и подписи карточек — обычный текст; при добавлении в HTML приложение обязательно экранирует их.

## Формат ответа

Приложение собирает токены выбранных карточек в одну строку через запятую и передаёт её в [`verify()`](../reference/api.md#verify). Например, порядок выбранных карточек не влияет на правильность, поскольку библиотека сравнивает набор токенов.

Каждый токен содержит 32 строчных шестнадцатеричных символа (`0–9`, `a–f`). Повторять один токен нельзя. Размер полученной строки ограничен 512 байтами. Ненужные пробелы или изменение регистра токенов недопустимы: приложение передаёт исходные значения, а проверку формата выполняет библиотека.

После успешного [`replace()`](../reference/api.md#replace) приложение показывает новую категорию и карточки и очищает прежние выбранные токены. Старые токены больше не относятся к новому заданию. Подробные условия обновления и истечения срока находятся в [описании жизненного цикла](../reference/lifecycle.md).

## Что важно для интерфейса

Текстовые карточки удобно оформлять стандартными элементами выбора с поддержкой клавиатуры и понятным обозначением выбранного состояния. Это упрощает создание [доступного интерфейса](../accessibility.md), но не делает его автоматически доступным для любого пользователя.

Проверка правильности всегда выполняется на сервере. Приложение не передаёт браузеру полный серверный каталог с отметками правильных карточек. Обязанности приложения при защите формы описаны в [модели безопасности](../security-model.md).

Некорректный каталог или настройки приводят к `InvalidArgumentException` при создании стратегии. Неверный набор токенов возвращает `Incorrect` либо `AttemptsExhausted` при исчерпании попыток. Эти результаты не следует путать с ошибками хранилища или генератора случайных значений.
