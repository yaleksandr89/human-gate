# CategorySelection — выбор карточек по категории

Пользователь видит название категории и выбирает все подходящие карточки. Например, среди фруктов и инструментов нужно выбрать только фрукты. **Порядок выбора не имеет значения.**

## Подключение и категории

Категории и подписи карточек задаются приложением. `CategorySelectionStrategy` выбирает случайные карточки и проверяет набор выбранных вариантов.

```php
<?php

use Yaleksandr\HumanGate\CategorySelection\CategorySelectionCategory;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionOptions;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionStrategy;

$strategy = new CategorySelectionStrategy(
    [
        new CategorySelectionCategory('Фрукты', ['Яблоко', 'Груша', 'Слива', 'Персик']),
        new CategorySelectionCategory('Инструменты', ['Молоток', 'Пила', 'Отвёртка', 'Клещи']),
    ],
    new CategorySelectionOptions(cardCount: 6, targetCount: 2),
);
```

Стратегия регистрируется в `ChallengeService`. Для создания этой капчи через [`ChallengeService::issue()`](../reference/api.md#issue) указывается `ChallengeKind::CategorySelection`. Пример полной сборки и работы с сессией приведён в [руководстве по интеграции](../guides/integration.md).

В одном каталоге допускается от 2 до 16 категорий, в каждой от 1 до 32 элементов. Для каждого варианта целевой категории должно хватать подходящих карточек, а в остальных категориях — карточек для отвлечения. Названия категорий и подписи элементов должны быть уникальны. Также важно избегать категорий, которые пересекаются по смыслу.

Подписи должны содержать корректный текст UTF-8 длиной от 1 до 80 **байт**, а не символов. Управляющие символы и пробелы по краям подписей не допускаются. Пакет возвращает текстовые подписи без готовой HTML-разметки.

## Количество карточек

`CategorySelectionOptions` позволяет менять число карточек и правильных вариантов:

| Параметр | По умолчанию | Допустимые значения |
| --- | --- | --- |
| `cardCount` | `6` | От `3` до `12` карточек |
| `targetCount` | `2` | От `1` до значения меньше `cardCount` |

Остальные карточки выбираются из других категорий. Срок действия и число попыток задаются общим [`Policy`](../reference/api.md#policy), а не `CategorySelectionOptions`.

## Данные для отображения

[`CategorySelectionPresentation`](../reference/api.md#данные-для-интерфейса) содержит `category` с названием категории и `cards` со списком карточек. Каждая `CategorySelectionCard` содержит видимую пользователю подпись `label` и случайный токен `token`.

Браузер получает карточки и их токены, но не сведения о том, какие карточки правильные. Пакет проверяет ответ по сохранённым на сервере данным.

## Формат ответа

Приложение соединяет токены выбранных карточек запятыми и передаёт строку в [`ChallengeService::verify()`](../reference/api.md#verify). **Порядок токенов не важен**: Human Gate сравнивает выбранный набор.

Каждый токен состоит из 32 строчных шестнадцатеричных символов (`0–9`, `a–f`). Токены не повторяются, длина всей строки не превышает 512 байт. Пробелы и изменение регистра токенов не допускаются. Исправлять или сортировать ответ перед передачей в пакет не нужно.

После успешного [`ChallengeService::replace()`](../reference/api.md#replace) приложение показывает новую категорию и карточки, а прежний выбор удаляет. Старые токены больше не подходят к новой капче. [Срок действия и обновление](../reference/lifecycle.md) одинаково работают для всех видов капчи.

## Ошибки

Некорректный каталог или настройки вызывают `InvalidArgumentException` при создании стратегии. Неверный ответ возвращает `VerificationCode::Incorrect` или `AttemptsExhausted` при исчерпании попыток. Ошибки хранилища обрабатываются отдельно. Подробнее об этих ситуациях — в [модели безопасности](../security-model.md) и [справочнике API](../reference/api.md#исключения).
