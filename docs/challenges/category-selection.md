# CategorySelection

## Назначение

Попросите пользователя выбрать все карточки, относящиеся к целевой категории. Приложение задаёт категории и подписи предметов; Human Gate подбирает карточки, выдаёт непрозрачные токены и проверяет ответ на сервере.

## Что видит пользователь

Пользователь видит название целевой категории и перемешанный набор текстовых карточек. Среди карточек есть элементы целевой категории и отвлекающие элементы из остальных категорий.

## Быстрый пример

Учебный каталог и конфигурация стратегии в composition root после подключения Composer autoload:

```php
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionCategory;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionOptions;
use Yaleksandr\HumanGate\CategorySelection\CategorySelectionStrategy;

$strategy = new CategorySelectionStrategy(
    [
        new CategorySelectionCategory('Фрукты', ['Яблоко', 'Груша', 'Слива', 'Персик']),
        new CategorySelectionCategory('Инструменты', ['Молоток', 'Пила', 'Отвёртка', 'Клещи']),
    ],
    new CategorySelectionOptions(cardCount: 6, targetCount: 2),
);
```

Зарегистрируйте `$strategy` в `ChallengeService`. При `issue()` и `replace()` явно передайте `ChallengeKind::CategorySelection`; по умолчанию они выбирают TextImage. Сборка и запросы показаны в [руководстве интеграции](../guides/integration.md).

## Каталог категорий

Пакет не поставляет нормативный семантический каталог. Приложение выбирает понятные и непересекающиеся по смыслу категории, затем проверяет содержание для своей аудитории.

`CategorySelectionCategory` содержит `label` и список `items`. Передайте в стратегию список из 2..16 категорий, в каждой — 1..32 предмета. Названия категорий уникальны; подписи предметов уникальны точным сравнением строк во всём каталоге.

Для любого возможного выбора целевой категории в ней должно быть не меньше `targetCount` предметов. Объединение остальных категорий должно содержать не меньше `cardCount - targetCount` отвлекающих предметов. Стратегия проверяет эти условия при создании.

Названия категорий и подписи предметов — обычный текст в корректном UTF-8, длиной 1..80 байт. Управляющие байты C0 и DEL запрещены, как и крайние ASCII `space`, `tab`, `CR`, `LF`. Ограничение задано в байтах, а не в числе видимых символов.

Уникальность строк не доказывает отсутствие смысловых пересечений. Эта часть каталога остаётся ответственностью приложения.

## Настройки

| Поле `CategorySelectionOptions` | По умолчанию | Ограничение |
| --- | --- | --- |
| `cardCount` | `6` | `3..12` |
| `targetCount` | `2` | Не меньше `1`, строго меньше `cardCount` |

Настройки и каталог проверяются при конструировании. Нарушения приводят к `InvalidArgumentException`, до выдачи задания.

## Presentation

`CategorySelectionPresentation` содержит `category` и список `cards`. Каждая `CategorySelectionCard` содержит `token` и `label`.

`category` и `label` — текст, а не HTML. Экранируйте их для фактического контекста вывода. Клиент получает случайный непрозрачный token и подпись, без серверного признака принадлежности карточки к целевой категории.

Presentation содержит 3..12 карточек с уникальными токенами и подписями. Приложение выбирает семантические элементы интерфейса и способ передачи данных; пакет не задаёт JSON-оболочку.

## Формат ответа

Отправляйте только выбранные непрозрачные токены через запятую. Каждый token — ровно 32 строчных hex-символа; повторения запрещены. Сырой ответ ограничен 512 байтами. Формат допускает 1..12 уникальных токенов, а правильный набор определяется серверным proof.

Порядок не важен: Human Gate выполняет каноническую сортировку. Приложение соединяет токены разделителем и не реализует свою trim/lowercase/deduplicate/sort канонизацию. Пробелы, верхний регистр, пустые части и повторения делают ответ некорректным.

Неверный набор и некорректный формат для активного задания дают `Incorrect` либо `AttemptsExhausted` на границе лимита. Остальные результаты определяются [жизненным циклом](../reference/lifecycle.md).

## Замена проверки

При успешном `replace()` используйте новый ID, новую категорию и новые карточки. Удалите все старые выбранные токены и состояние выбора интерфейса.

Старый ID возвращает `Replaced`, пока его терминальная запись сохранена. Сохранённое истёкшее задание может допускать замену; после удаления записи старый ID возвращает `NotFound`. Условия описаны в [жизненном цикле](../reference/lifecycle.md).

## Безопасность

Проверку правильности выполняет сервер. Браузер получает данные задания без списка правильных токенов и признака принадлежности к цели. Открытый ответ не хранится в авторитетном состоянии; proof связан с ID, purpose, kind и каноническим ответом.

Не рассчитывайте правильность на клиенте и не передавайте клиенту серверный каталог с дополнительной разметкой правильного набора. Случайные токены не заменяют авторизацию, CSRF или ограничение частоты запросов. [Модель безопасности](../security-model.md) описывает общую границу доверия.

## Доступность

Текстовые подписи делают CategorySelection наиболее удобным из трёх типов для семантического интерфейса. Используйте нативные интерактивные элементы, общее понятное задание, поддержку клавиатуры и видимое и объявляемое состояние выбора.

Автоматического соответствия требованиям доступности пакет не обещает. Ясность категорий и доступность готового интерфейса проверяет приложение. [Рекомендации по доступности](../accessibility.md) описывают общие правила.

## Типичные ошибки

- Смысловое пересечение категорий при формально уникальных строках.
- Недостаток целевых или отвлекающих предметов для выбранных options.
- Оценка лимита 80 байт как 80 символов Unicode.
- Вывод подписей без экранирования или использование их как HTML.
- Передача подписей вместо токенов либо исправление некорректных токенов перед `verify()`.
- Повторное использование выбора после замены задания.

Ошибка источника случайности может передаться как `Random\RandomException`; инфраструктурные сбои storage обрабатываются отдельно от неверного ответа. Категории ошибок собраны в [API](../reference/api.md).
