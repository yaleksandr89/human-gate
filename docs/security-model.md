# Модель безопасности

Human Gate создаёт капчу и проверяет ответы на сервере. Пакет ограничивает время действия капчи и число неверных попыток, а после правильного ответа не позволяет пройти ту же капчу повторно.

## Проверка на сервере

При создании капчи приложение задаёт серверный ключ [`Purpose`](reference/api.md#основные-типы), который указывает, для какой формы или операции она предназначена. Например, `contact.send` можно использовать для формы обратной связи, а `account.register` — для регистрации. Проверить капчу, созданную для одной формы, как капчу другой формы нельзя. Правильный ответ и данные для его проверки остаются на сервере; браузер получает только идентификатор и сведения для отображения капчи.

При отправке формы приложение передаёт идентификатор и ответ в [`ChallengeService::verify()`](reference/api.md#verify). Правильность определяется на сервере: переданный идентификатор сам по себе не означает, что капча пройдена.

Пакет не хранит правильный ответ в открытом виде. Для [`CategorySelection`](challenges/category-selection.md) и [`IconSequence`](challenges/icon-sequence.md) браузеру передаются случайные токены вариантов, но не сведения о правильном выборе. Для карточек порядок токенов не имеет значения, для последовательности значков он важен.

## Время действия и повторное использование

Срок действия капчи и число неверных попыток задаются через [`Policy`](reference/api.md#policy). По умолчанию капча действует 180 секунд; третья неверная попытка завершает проверку.

Правильный ответ возвращает `VerificationCode::Accepted`, после чего ту же капчу нельзя использовать снова. Пока запись об успешной проверке хранится, повтор возвращает `AlreadyConsumed`. После удаления записи возвращается `NotFound`. Оба результата означают, что старый идентификатор не подходит для повторного прохождения проверки.

Истёкшая капча также не принимается. Подробности об [обновлении и сроке хранения записей](reference/lifecycle.md) приведены в описании жизненного цикла.

## Хранение данных

Готовый [`NativeSessionChallengeStore`](reference/api.md#хранилище-и-время) работает с обычной сессией PHP, которую открывает приложение, используя обработчик `files`. При изменении данных пакет сохраняет их и проверяет запись. Если сохранить изменения не удалось, метод завершится исключением, а не успешной проверкой.

Как подключить хранилище и работать с сессией, показано в [руководстве по интеграции](guides/integration.md#хранение-в-сессии-php).

## Ограничения активных капч

Параметры [`Policy::maxActive` и `Policy::maxActivePerPurpose`](reference/api.md#policy) задают количество одновременно действующих капч, которые можно хранить. Эти значения не измеряют число HTTP-запросов за промежуток времени.
